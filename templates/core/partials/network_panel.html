{% comment %} The Networks tab body, shared by the cluster and node scopes (5a4B-ii). Three rules this markup holds: * **One panel per node, never one merged table.** A bridge name is not a cluster object: `vmbr0` on pve1 and `vmbr0` on pve2 are different devices with possibly different ports, and one row for both would show one node's ports under the other's name. * **An empty list is never rendered as "no network".** A node whose state is not current says why instead of showing an empty table, because "nobody read this node" and "this node has no bridges" are opposite instructions. * **One table per layer, with that layer's columns.** The layers disagree about which columns carry meaning: a physical port has no address, ports, VLAN or comment, and a vnet's VLAN lives in SDN rather than on this endpoint. A shared nine-column table answered every question for every row and so rendered mostly `-` — and worse, printed a truthful-looking `no` under VLAN for seven vnets that are each tagged. A column a section cannot answer is absent from it. Sections are separate tables rather than separator rows inside one, so that sorting a column stays inside its layer instead of scattering the grouping on the first click. {% endcomment %} {% for group in panel.groups %}
